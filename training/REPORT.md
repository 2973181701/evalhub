# Qwen3-1.7B 约束遵循微调 · 实验报告

> 数据：91 条蒸馏样本 / 评测：20 题（与训练题**零重叠**）/ 硬件：RTX 4060 Laptop 8GB
> 结论一句话：**微调达成了「说短」的目标（规范性 40%→80%，补测修正为 75%、延迟减半），
> 但平台原有的规则评分反而下降 0.39 —— 因为那个指标在奖励啰嗦。本轮已把「约束遵循」并进评分口径。**

## 三、为什么两个指标会反向

不是训练失败，是**评分口径有偏**。三处证据：

1. **标签题**：E01 题目要求「只给标签」，微调输出「负面」两个字——**完全正确**；base 输出 117 字的分析。规则分：base 4.70 / 微调 3.70。准确率两者都是 5.00，扣的是 completeness 与 expression —— 纯粹因为答案短。
   E03 更极端：base 4.60 → 微调 2.70（−1.90），微调只回「正面」。

2. **代码题**：C03 微调输出 `def reverse_string(s): return s[::-1]`（37 字，可解析），base 输出 561 字带讲解。规则分 2.40 vs 3.20 —— 短的反而低。

3. **相关性**：把两份回答共 40 个样本放在一起，答案长度与规则总分的相关系数 **r = +0.196**，方向为正：越长越容易拿分。因为 accuracy 用的是词面重合，答案越长越可能覆盖参考词。

这与之前 Judge 实验的结论一致：规则判优与人只有 κ≈0.075 的一致度。**这套规则分适合做回归冒烟，不适合做「回答质量」的判定。**

## 五、诚实的边界

1. **指标 A 的下降是真实存在的**，不能因为「我们觉得规则分有偏」就宣布它无效。正确表述是：**两个指标衡量的是不同东西**，规则分衡量「与参考文本的覆盖度」，规范性衡量「是否符合题目要求」。要判断该不该上线，还需要人的判断——这正是标注队列存在的意义。
2. **样本太小**：训练 91 条、评测 20 条。规范性从 40%→80% 的置信区间很宽（n=20，一个样本就是 5 个百分点）。
3. **任务是窄的**：只训练了「守约束」，没有训练知识或推理能力；逻辑推理 2/4 里错的仍是真推理错误。
4. **蒸馏而非人工**：训练目标来自 GLM 生成，不是人工标注。模型学到的是「GLM 的简洁风格」，不是「人类偏好的答案」。
5. **没做留出集**：91 条全用于训练，没有划分验证集。loss 只能说明拟合，不能说明泛化；泛化证据来自 20 题评测（不同题目），但那是测试集不是验证集。
6. **单次运行**：没有多 seed，无法区分「微调效果」与「采样噪声」——虽然贪心解码把推理侧噪声消掉了。

## 六、补测：把「约束遵循」并进评分口径（后续轮次）

上一轮的建议是「给规则引擎加一个约束遵循维度」。这一轮做完了，做法和结果如下。

**做法**：新增 MoonBit 纯函数 `core/src/engine_constraint.mbt`，从**题面**解析可机检约束
（字数上限 / 句数 / 标签集合 / 代码 / 两步 / JSON），不看题目 ID、不看参考答案。
输出三个新字段：`constraint`（0–5，只看适用项）、`gate`（pass/warn/fail）、
`gated_total`（违规时封顶）。五维 `total` 一字未改，历史 run 的对比仍然有效。

封顶规则集中在 `gate_cap`：全过不封顶，1 条不过封顶 3.5，≥2 条封顶 2.0。
空答案单列判 fail —— 否则它会「通过」字数上限那一项。

**回测**（`node tools/rescore_constraints.mjs`，40 条已有回答，不重跑模型）：

| | 五维总分 | 约束分 | 门禁后 | pass/warn/fail |
|---|---:|---:|---:|---|
| base | 4.03 | 4.10 | 4.03 | 20/0/0 |
| 微调 | 3.64 | **4.85** | 3.64 | 19/1/0 |

| 长度相关性（n=40） | r |
|---|---:|
| 答案长度 vs 五维总分 | **+0.200**（与本报告上一版的 +0.196 一致，可复算） |
| 答案长度 vs 约束分 | **−0.620** |
| 答案长度 vs 门禁后总分 | +0.200 |

**三条结论，其中一条是认错。**

1. **上一版漏判了一条违规。** 上一版的六条判据里没有「用几句话」这一项
   （`check_compliance.py` 只对 R02 硬编码了两步检查），所以 W02 题（要求 3 句话）
   微调只写了 1 句，仍被判为「合规」。新引擎从题面解析出 `sentence_count=3`，抓到了。
   即：**规范性 80% 这个数字偏高，按「句数也算约束」应修正为 75%（15/20）**——
   少 1 条不改变方向，但数字该修。
2. **门禁没有翻转总分排序。** 微调在约束分上明显更好（4.85 vs 4.10），
   但违规封顶只影响 1 条，总分仍是 3.64 < 4.03。**不为了好看去改封顶系数。**
3. **约束分不能单独当质量分。** 它与长度负相关（−0.620），说明「越短越容易守约束」；
   一个永远回「负面」的模型约束分满分而内容全错。所以它有且只有两个用途：
   门禁（违规封顶）与诊断（哪类约束没守住）。质量判定仍要靠五维 + 人工标注。
